# Visual Folder Explorer v1.6.0

Visual Folder Explorer — Windows-застосунок для роботи з папками, де зберігаються великі набори зображень разом із TXT/Markdown-описами.

**v1.6.0 додає вибіркове очищення описових метаданих зображень і відео.** Перед змінами програма показує властивості Windows, створює й перевіряє резервну копію. Очищуються лише обрані поля «Назва», «Тема», «Примітки», «Автори», без запуску кодеків перекодування.



## Що нового у v1.6.0

- Додано кнопку **«Очистити метадані»** в панелі операцій із зображеннями. Підтримано або вибрані плитки зображень, або всі підтримувані файли поточної папки, включно з відео.
- Перевіряються чотири властивості Windows: `System.Title` («Назва»), `System.Subject` («Тема»), `System.Comment` («Примітки»), `System.Author` («Автори») для `.jpg`, `.jpeg`, `.png`, `.mp4`, `.m4v`, `.mov`. Можливість читання/запису залежить від установленого у Windows обробника метаданих конкретного формату.
- В окремому сучасному вікні є preview **«до → після»**, вибір файлів і окремі прапорці чотирьох полів.
- Резервні копії створюються **обов'язково** у `<поточна папка>/_VFE_MetadataBackups/<час>_<ідентифікатор>/`. До будь-якої зміни байти копії звіряються з оригіналом через SHA-256.
- Для очищення використовується системний Windows `IPropertyStore` із `VT_EMPTY` та `Commit`: власного перекодування картинки чи відео немає. Для JPEG/PNG додатково порівнюється SHA-256 від декодованих пікселів до/після. Після зміни кожне поле перевіряється повторним читанням.
- Коли запис не підтримується або перевірка не пройшла, вихідний файл відновлюється з резервної копії. Помилки відображаються по кожному файлу; невідомі формати не змінюються.
- Дати створення/зміни файла зберігаються, наскільки це дозволяють права файлової системи. Після успіху preview оновлюється з диска.
- Додано підтвердження, progress, UA/EN, кнопку **«Відкрити резервні копії»** і `restore-map.json` з адресами оригіналів та копій.

**Важливі обмеження:** це очищення **лише чотирьох властивостей Windows**, а не повне видалення EXIF, XMP, геолокації, даних пристрою або прихованих тегів. Для окремих MP4/MOV Windows надає лише читання, тому програма повідомить про неможливість очищення без примусового перепакування. Сам додаток не перекодовує медіа, однак спосіб збереження метаданих визначає Windows property handler. Для цінних оригіналів спочатку протестуй один файл, а резервні копії зберігай. У копіях вихідні метадані залишаються.

## Що нового у v1.5.2

- Елемент `...` для переходу до батьківської папки **закріплено під заголовком «Провідник»** і винесено за межі списку з прокруткою. Тепер він не зникає під час гортання сотень папок і TXT/MD-файлів.
- Одне натискання на закріплене `...` відкриває батьківську папку. Drag & Drop на цей елемент і надалі використовує батьківську папку як адресу призначення. У корені диска `...` залишається видимим, але недоступним для переходу вгору.
- Під час перейменування файла за замовчуванням виділяється **лише назва без розширення**: `text.txt` → виділено тільки `text`. Перейменування папок і створення нових файлів зберігають звичайне повне виділення.
- У v1.5.2 очищення ще не було; з v1.6.0 доступний окремий безпечний режим із резервною копією та підтвердженням.

## Що нового у v1.5.1

- Під час перетягування повзунка порогу схожості тепер змінюється лише число відсотків; перебудова груп запускається тільки після того, як повзунок відпущено. Це дозволяє нормально рухати slider навіть у папках із сотнями або тисячами картинок.
- При керуванні порогом клавіатурою зміни також застосовуються після відпускання клавіші навігації.
- У «Провіднику» над папками/текстовими файлами завжди є елемент `...` для переходу на один рівень вище.
- Для `...` контекстне меню містить лише безпечну дію **«На рівень вище»** — перейменування, видалення та вирізання недоступні.
- Drag & Drop на `...` використовує батьківську папку як місце призначення.

## Що нового у v1.5.0

- До панелі **«Операції з зображеннями»** додано **«Групувати за схожістю»**.
- Аналіз повністю локальний і використовує 63-бітний perceptual hash на основі низькочастотного DCT (pHash-підхід), а не SHA-256.
- **«Дублікати»** залишаються окремою функцією для байт-в-байт однакових файлів; новий режим шукає візуальну схожість, у тому числі після resize або повторного JPEG/WebP-стиснення.
- Додано запам'ятовуваний **поріг схожості**. Вищий відсоток дає суворіші групи, нижчий — ширші.
- Хеші рахуються один раз за аналіз. Після цього зміна порогу миттєво перебудовує групи без повторного читання всіх оригіналів.
- Додано preview груп із thumbnails, середньою схожістю, кількістю груп/файлів та checkbox для кожної картинки. Зняті з вибору файли залишаються у поточній папці.
- До підтвердження **«Створити папки та розкласти»** нічого не переноситься.
- За замовчуванням створюються `Similar_001`, `Similar_002`, ...; префікс можна змінити. Уже зайняті назви папок безпечно пропускаються.
- Конфлікти назв файлів усередині нових папок і надалі вирішуються через `_1`, `_2`, ...
- Картинки, які не потрапили в жодну групу, залишаються на місці.
- Для великих папок аналіз виконується паралельно з progress і лічильником файлів, які не вдалося прочитати.
- Watcher відкритої папки тимчасово вимикається, поки відкрите вікно схожості, щоб масове перенесення не запускало зайві background refresh.

## Вимоги

### Для користувача

- Windows 10 або Windows 11 x64;
- використовуйте **self-contained опубліковану збірку** — вона не потребує встановленого .NET SDK або .NET Desktop Runtime.

### Для розробника / ПК, де збирається програма

- .NET 10 SDK або Visual Studio 2022 з workload **.NET desktop development**;
- для звичайної локальної розробки `StartDev.bat` використовує `NuGet.Offline.Config`; у проєкті немає сторонніх `PackageReference`. `NuGet.Config` залишається для CI/self-contained publish runtime-пакетів.

## Запуск / публікація

### Розробка

- відкрийте `VisualFolderExplorer.sln` у Visual Studio та натисніть **F5**, або
- запустіть `StartDev.bat` на ПК, де є .NET 10 SDK.

`StartDev.bat` тепер використовує локальний `NuGet.Config`, тому блокування `api.nuget.org` корпоративним firewall більше не має ламати цей проєкт, якщо у встановленому SDK вже є Windows Desktop reference packs.

### Готова програма без встановлення .NET

На **ПК розробника/збірки** запустіть `PublishWin64.bat`. Буде створено:

`publish\win-x64-portable\`

Скопіюйте всю цю папку на потрібний ПК і запустіть `VisualFolderExplorer.exe`. На цільовому ПК **не потрібно** встановлювати .NET або SDK.

`PublishSingleFileWin64.bat` додатково створює self-contained single-file варіант. Для жорстко контрольованих корпоративних ПК я б використовував portable self-contained папку: її простіше перевірити й офіційно allowlist-нути IT-службі, ніж self-extracting single-file bundle.

GitHub Actions тепер автоматично створює обидва варіанти.


## Корпоративне розгортання

Self-contained збірка прибирає залежність від встановленого .NET, але **не обходить** корпоративні політики безпеки. Запуск може контролюватися Microsoft Defender, SmartScreen, AppLocker, WDAC, EDR або внутрішніми allowlist-політиками.

Для нормального легітимного розгортання:

- використовуйте self-contained **portable folder**;
- підписуйте `VisualFolderExplorer.exe` Authenticode-сертифікатом, якому довіряє організація;
- попросіть IT allowlist-нути підписаного видавця або погоджений hash/path відповідно до політики компанії;
- для масового розгортання пакуйте підписану збірку в MSI/MSIX через стандартний корпоративний канал.

Детальніше — у `DEPLOYMENT.md`.

## Основні можливості

- Блок «Провідник» із папками та файлами `.txt` / `.md`.
- Плитки зображень із сортуванням за назвою, датою зміни, датою створення та розміром у прямому/зворотному порядку.
- Поступове асинхронне завантаження прев'ю, щоб великі папки не блокували інтерфейс.
- Постійний кеш мініатюр у `%LOCALAPPDATA%\VisualFolderExplorer\thumbcache`.
- Велике прев'ю з 300% zoom та перетягуванням мишею; метадані показуються у заголовку «Перегляд» і ховаються під час zoom.
- Маркер останньої вибраної картинки біля скролбара блока «Зображення».
- Редагування тексту, збереження та попередження про незбережені зміни.
- Markdown за замовчуванням відкривається у відформатованому вигляді з можливістю перейти до редагування розмітки.
- Стрілки між текстовими файлами синхронізовані з вибором у «Провіднику».
- Копіювання, вирізання, вставлення, перейменування, створення та видалення файлів/папок.
- Видалення відбувається через Кошик Windows.
- Конфлікти назв під час вставлення автоматично отримують `_1`, `_2` тощо.
- Мультивибір зображень через Ctrl/Shift для копіювання/вирізання.
- Окреме стилізоване вікно перенесення зображень із запам'ятовуванням останньої папки призначення та автоматичним перейменуванням при конфліктах.
- Власне стилізоване вікно вибору папок.
- Перемикач UA / EN із запам'ятовуванням мови.
- Зберігаються розмір/стан вікна, остання папка, сортування, мова, остання картинка та остання адреса перенесення.

## Архітектура

Після переходу на C# логіку рознесено по окремих частинах:

- `MainWindow.xaml/.cs` — головний UI та координація;
- `Models/` — моделі провідника та зображень;
- `Services/SettingsService.cs` — збереження налаштувань у JSON;
- `Services/ThumbnailService.cs` — асинхронні мініатюри та кеш;
- `Services/FileService.cs` — буфер обміну, кошик, копіювання/переміщення, конфлікти назв;
- `Services/LocalizationService.cs` — українська/англійська локалізація;
- `Services/MarkdownService.cs` — базовий Markdown-renderer;
- `Windows/` — повторно використовувані стилізовані вікна;
- `Resources/Styles.xaml` — єдиний файл стилів для кнопок, меню, полів, ComboBox, списків, діалогів та інших елементів.

## Єдині стилі

Усі нові UI-елементи мають використовувати `Resources/Styles.xaml`. Для базових контролів також є неявні стилі, тому нові кнопки, поля, ComboBox, контекстні меню, MenuItem, розділювачі та скролбари відразу отримують єдиний вигляд.

## Оптимізація великих папок

C#-версія покращує роботу з 200–1000+ картинок завдяки:

- одному скануванню каталогу під час переходу;
- пакетному додаванню елементів;
- обмеженій кількості паралельних thumbnail-задач;
- декодуванню у фоні;
- прев'ю 240 px для плиток;
- `Freeze()` для WPF bitmap;
- постійному thumbnail cache;
- скасуванню попереднього завантаження, якщо користувач швидко змінив папку або сортування.

Поточна сітка все ще використовує WPF `WrapPanel`; у майбутній версії можна додати справжню віртуалізацію плиток для бібліотек у декілька тисяч зображень.

## Налаштування та кеш

Налаштування:

`%LOCALAPPDATA%\VisualFolderExplorer\settings.json`

C#-версія зберігає назви основних полів старого settings.json, тому сумісні налаштування з PowerShell-версії можуть бути використані повторно.

Кеш прев'ю:

`%LOCALAPPDATA%\VisualFolderExplorer\thumbcache`

## Підтримувані формати

JPG, JPEG, PNG, BMP, GIF, TIFF/TIF та WEBP, якщо Windows/WPF має відповідний codec.

## Версійність

Використовується Semantic Versioning:

- PATCH — виправлення й невеликі сумісні зміни;
- MINOR — нові сумісні функції;
- MAJOR — великі/несумісні зміни або зміна архітектури.

Переписування PowerShell → C# випущене як **v1.0.0**. Починаючи з **v1.1.1**, поточний C# WPF-проєкт орієнтований на **.NET 10**; у v1.2.1 стандартний вибір папок реалізовано через WPF `Microsoft.Win32.OpenFolderDialog`; Windows Forms більше не підключається.

## GitHub Actions artifact

GitHub Actions тепер завантажує **готову portable-папку напряму як artifact**. GitHub сам формує один ZIP, тому після завантаження потрібно виконати лише одне розпакування. Усередині одразу знаходяться `VisualFolderExplorer.exe`, runtime-файли та `BUILD_INFO.txt` із SHA-256 хешем EXE. Вкладеного ZIP більше немає.
